# Writing Guidelines for Futtoboru Community Content

## Overview

This document provides guidelines for writing Patreon updates, social media posts, and other community-facing content for Futtoboru.

---

## Tone & Voice

### Core Principles
- **Friendly & Engaging:** Write as if talking to friends who are excited about the project
- **Transparent:** Be honest about challenges and progress
- **Enthusiastic:** Show passion for the project
- **Professional but Accessible:** Technical but understandable
- **Authentic:** Be genuine, don't oversell

### Voice Characteristics
- Conversational, not corporate
- Technical when needed, but always explained
- Positive but realistic
- Appreciative of supporters
- Excited about progress

---

## Content Structure

### Patreon Updates

#### Required Sections
1. **What's New This Week** - Lead with wins
2. **What We're Working On** - Current focus
3. **Progress Update** - Metrics and percentages
4. **What's Next** - Roadmap visibility
5. **Thank You** - Appreciation

#### Optional Sections
- Community Highlights
- Behind the Scenes
- Questions & Answers
- Visual Updates

### Social Media Posts

#### Formats
- **Announcements:** Feature releases, milestones
- **Progress Updates:** Quick wins, weekly summaries
- **Behind the Scenes:** Development process
- **Community Engagement:** Questions, polls, feedback requests

---

## Writing Tips

### Do's
✅ Start with wins and positive news  
✅ Use specific numbers and metrics  
✅ Explain technical concepts simply  
✅ Show progress visually (percentages, charts)  
✅ Be honest about challenges  
✅ Engage with questions  
✅ Thank supporters genuinely  
✅ Use emojis sparingly but effectively  

### Don'ts
❌ Oversell or overpromise  
❌ Use jargon without explanation  
❌ Ignore setbacks or delays  
❌ Be overly technical  
❌ Forget to thank supporters  
❌ Make excuses  
❌ Compare negatively to competitors  

---

## Technical Content

### Explaining Technical Concepts

**Bad:**
"We implemented a Map<Long, Long> for staff tracking."

**Good:**
"We needed a way to track which staff members work at each club. We solved this by using a simple mapping system that connects staff positions to specific people - think of it like a company directory that tells you who holds each job."

### Balancing Technical Depth

- **Casual Supporters:** Focus on what it means for gameplay
- **Technical Supporters:** Include implementation details in "Behind the Scenes"
- **Everyone:** Explain the "why" behind decisions

---

## Progress Communication

### Using Percentages
- Be specific: "40% complete" not "almost done"
- Explain what the percentage means
- Show progress over time when possible

### Handling Delays
- Acknowledge delays early
- Explain the reason (briefly)
- Provide new timeline
- Don't make excuses, just be transparent

### Celebrating Milestones
- Make milestones feel significant
- Show what it means for the project
- Thank supporters for making it possible

---

## Community Engagement

### Responding to Feedback
- Acknowledge all feedback
- Thank supporters for suggestions
- Explain if/when features might be added
- Be honest about limitations

### Asking for Input
- Make questions specific
- Provide context
- Show you value their opinion
- Follow up on decisions made

### Handling Criticism
- Listen actively
- Respond professionally
- Acknowledge valid points
- Don't be defensive

## Visual Content

### Screenshots
- Show new features in action
- Before/after comparisons
- Progress indicators
- UI improvements

### GIFs/Videos
- Feature demonstrations
- Gameplay snippets
- Development process
- Behind-the-scenes

### Charts/Graphs
- Progress tracking
- Metrics over time
- Roadmap visualization

## Update Frequency

### Recommended Schedule
- **Weekly:** Short updates (200-400 words)
- **Bi-weekly:** Detailed updates (500-800 words)
- **Monthly:** Comprehensive updates (800-1200 words)
- **Major Milestones:** Special updates (1000+ words)

### Best Days to Post
- **Monday:** Start of week energy
- **Friday:** End of week summary
- **Mid-week:** If weekly, Wednesday works well

---

## Examples

### Good Update Opening
"Hey Futtoboru supporters! This week we hit a major milestone - the job system foundation is complete! 🎉 This means unemployed managers can now browse clubs, see open positions, and apply for jobs. Let me show you what we built..."

### Good Progress Update
"We're making steady progress toward v1.0! Phase 1 (Bug Fixes) is 40% complete, with most critical issues identified and being fixed. Phase 2 (Match Engine) is in the design phase, and we're excited to start implementation next week."

### Good Technical Explanation
"One challenge we faced was tracking club staff without creating circular references in our data model. We solved this by using a simple mapping system (think of it like a phone book - you look up a position and find who holds it). This keeps our code clean and makes it easy to query which clubs have open positions."

## Checklist

Before publishing any update, ensure:
- [ ] Starts with positive news
- [ ] Includes specific metrics/percentages
- [ ] Explains technical concepts simply
- [ ] Shows progress clearly
- [ ] Thanks supporters
- [ ] Includes what's next
- [ ] Proofread for typos
- [ ] Appropriate length for update type
- [ ] Visuals included if relevant
- [ ] Links to resources included
